🎯 Allocation Validation Feature Demo

Overview

This demo showcases the new allocation validation feature that prevents resource overallocation and provides clear user feedback.

Key Features

  • Real-time validation when adding or updating allocations
  • Prevents person overallocation (total PM > FTE)
  • Prevents project overallocation (total PM > planned budget)
  • Clear warning messages with specific conflict details
  • User choice to proceed or cancel
  • Respects time-based changes in FTE and budgets

Validation Rules

✓ Valid Allocation

Person FTE Allocation PM Result
Alice Smith 1.0 0.5 ✓ Allowed (0.5 ≤ 1.0)

User Experience: Allocation is added without any warnings.

⚠️ Person Overallocation

Person FTE Existing PM New PM Total PM Result
Alice Smith 1.0 0.6 0.5 1.1 ⚠️ Warning (1.1 > 1.0)
⚠️ OVERALLOCATION WARNING for Alice Smith Person would be overallocated in 6 month(s): 2025-01, 2025-02, 2025-03. For example, in 2025-01: FTE=1.00, existing=0.60 PM, new allocation=0.50 PM, would exceed FTE by 0.10 PM. Do you want to proceed anyway? This may cause resource conflicts.

User Experience: Warning dialog appears with specific details. User can:

  • Click OK to proceed with overallocation
  • Click Cancel to abort the allocation

⚠️ Project Overallocation

Project Planned PM Existing PM New PM Total PM Result
Project Alpha 5.0 3.0 4.0 7.0 ⚠️ Warning (7.0 > 5.0)
⚠️ OVERALLOCATION WARNING for Project Alpha Project would be overallocated in 11 month(s): 2025-02, 2025-03, 2025-04. For example, in 2025-02: Planned=5.00 PM, existing=3.00 PM, new allocation=4.00 PM, would exceed budget by 2.00 PM. Do you want to proceed anyway? This may cause budget overruns.

User Experience: Warning dialog appears with budget details. User can choose to proceed or cancel.

Advanced Scenarios

🔄 Time-Based FTE Changes

The validation respects FTE changes over time:

Period FTE Allocation PM Result
Jan - Feb 2025 1.0 0.8 ✓ OK
Mar - Jun 2025 0.5 0.8 ⚠️ Warning (exceeds)

If you allocate 0.8 PM from Jan-Jun, you'll see a warning because it exceeds the reduced FTE starting in March.

📊 Allocation Overrides

The validation accounts for month-specific allocation overrides:

  • Base allocation: 0.5 PM per month
  • Override for March: 0.8 PM
  • If adding another 0.3 PM allocation for March, total = 1.1 PM (warning if FTE = 1.0)

Performance Considerations

The validation is designed to be performant:

  • Validates only affected months (limited to 60 months for open-ended)
  • Early exit when first conflict is found (for user feedback)
  • Reuses existing data (no additional database queries)
  • Validation runs asynchronously to not block UI
